# Archetipo Composizionale: Nested-CTE (CTE contenente subquery)

## Descrizione del Pattern

Intrecciare mutualmente CTE e subquery nella direzione PostgreSQL-valida: una CTE il cui corpo contiene a sua volta una subquery annidata (`IN (SELECT ...)`, subquery scalare, `EXISTS`). BEAVER isola esplicitamente questo costrutto ("Nested-CTE"). NOTA: in PostgreSQL la clausola `WITH` è ammessa solo al livello più esterno della query; la direzione inversa (una subquery che contiene un `WITH`, "CTE-Nested") non è sintatticamente valida in PostgreSQL e viene pertanto esclusa. (Zero-Data: il modello deve inventare un dominio complesso con una chiave esterna implicita, e calcolare un insieme intermedio tramite CTE filtrando con una subquery annidata su un'altra relazione.)

Esempio di composizione SQL (enterprise — CTE che isola i clienti ad alto valore tramite subquery, poi aggrega per distretto):

```sql
WITH high_value_customers AS (
  SELECT c.id, c.name, c.district_id
  FROM customers c
  WHERE c.id IN (SELECT o.customer_id FROM orders o WHERE o.amount > 1000)
)
SELECT d.name AS district, COUNT(hvc.id) AS vip_count
FROM high_value_customers hvc
JOIN districts d ON hvc.district_id = d.id
GROUP BY d.name;
```
